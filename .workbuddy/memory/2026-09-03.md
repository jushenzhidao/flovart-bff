## M2 续 2：PSD 下载 blob URL 报错修复（favicon->PSD 200 但前端 400）

- 浏览器报错：`url=blob%3Ahttp%3A%2F%2F127.0.0.1%3A37522%2F<uuid>` → vite proxy 400 strict-origin-when-cross-origin。
- 根因：Flovart 把生成的图存 IndexedDB 后用 `URL.createObjectURL` 给 `<img>` 用，前端拿到的 mediaUrl 是 `blob:` 浏览器内存地址，**服务端 httpx 无法解析 blob://**。
- 修法：BFF `app/routers/convert.py` 新增 **POST /api/convert/image**（multipart/form-data，`file`+`format`）；前端 `downloadMedia.ts` PSD 分支改为 `fetch(blobUrl).blob()` → FormData.append('file', file) → POST。
- 副作用：FastAPI multipart/form-data 需要 `python-multipart` 包，否则启动失败 `Form data requires "python-multipart" to be installed` —— requirements 加 `python-multipart>=0.0.9`。
- 端到端验证 PNG→PSD POST 200，size 79626，magic 8BPS。
- GET ?url= 直链路径保留（适用于 new-api 直接托管的媒体 URL，节省 base64 带宽）。

## M2 续 10：PSD 下载黑底 bug 修复（透明背景图被填黑）
- 现象：飞哥下 PSD 在 PS 里打开看到「黑底图」（PNG 透明背景图丢失）。
- 真根因：convert.py `_pil_from_bytes` 强制 `convert('RGB')` 把 alpha 通道直接丢了，下游 `PSDImage.new(mode='RGBA')` 收到的是 RGB 图，写出 channels=3。
- 修法：①`_pil_from_bytes` 不再强制 RGB，1/P/PA 按需转 RGBA/L，其他模式原样；②`_pil_to_psd_bytes` 用 `getbands()` 检测 alpha，决定 `psd_mode='RGBA'` 或 `'RGB'`；3 步顺序按 P/1/PA 显式 map（避免 P 调色板的半透明落到 RGBA）。
- 验证：POST /api/convert/image 上传真实 RGBA PNG → 写出 PSD channels=4 colormode=3，corner composite `(255,255,255,0)` alpha=0（透明保留），中心 `(200,50,80,255)` 全不透明。
- 教训：**写文件格式时不能无脑强制 RGB，要按源图 mode 派决定写格式**。Pillow 强制 RGB 在图像转换时非常常用，但在写 PSD 这种支持 alpha 的格式时一定要保留 alpha。

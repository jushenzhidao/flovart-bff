## 管理员 PAT 互踢根治（2026-09-20，flovart-bff + hewapi 双侧落地）
- 痛点：两 BFF 共用 uid=1 + 同 PAT 连同一台 new-api。旧逻辑 401 → 盲目 `_admin_login()`（GET /api/user/token 轮换 PAT）→ 互作废对方 → 乒乓 → 50 会话/100 签发双爆 → 「登录设备数已达上限」死锁（new-api 会话永不过期）。
- 根治三件套（两仓库同构实现）：
  1. `_reload_admin_cred()`：401 先重读共享凭据文件，对端已轮换落盘就直接采纳，绝不 login；
  2. `_self_heal_admin_cred()`：文件无新值 → 锁内双检（①缓存 PAT 已变=同进程治愈 ②重读文件=跨进程治愈）→ 仍无效才 login，单飞锁防并发双轮换；`_save_admin_cred(force=True)` 强制落盘（env 直供也写）；
  3. `NEWAPI_ADMIN_LOGIN_FALLBACK=0` 可禁自动轮换转人工。
- 部署：两边 compose 共挂外部卷 `flovart-admin-cred` → /shared，`BFF_ADMIN_CRED_FILE=/shared/admin_cred.json`（flovart 负责 name+create，hewapi external:true 引用；先起 flovart 或手动 docker volume create）。flovart 的 BFF_ADMIN_CRED_FILE 从 /data/admin_cred.json 改到 /shared —— **旧缓存 PAT 作废需重新登录一次落盘**。
- 测试：flovart tests/test_admin_cred_selfheal.py 11 个（全量 138 passed）；hewapi 同款 11 个（全量 5 个失败为基线遗留：static/docs.js ✓ emoji 门禁 + docs 档案目录，与本次无关）。
- 应急脚本同步到 flovart：scripts/clear_sessions.py（auth_version 抬升吊销全部会话解死锁，⚠️ 连带作废该账号 PAT，用后必须重登换新）+ fix_session_limit.py。
- ⚠️ 面板「生成令牌」仍会作废 PAT：现在两边会经共享文件自愈（第一个 401 触发轮换、第二个 401 读文件），最多一轮收敛，不再乒乓。

## ⚠️ 修正：两 BFF 不在同一台服务器（飞哥 2026-09-20 指出）→ 方案改为「读回恢复」
- 共享卷方案作废（Docker volume 跨不了机器，hewapi 侧 external 引用还会起不来）。两份 compose 已回退：各自用本地 /data/admin_cred.json 缓存，删除 flovart-admin-cred 卷。
- **新核心：读回恢复 `_recover_admin_pat_by_readback()`**：401 自愈序列 = ①重读本地凭据文件（同机多实例用）→ ②锁内双检 → ③**login 拿会话后 GET /api/user/self 把账号当前 access_token 原样读回来**（读操作不轮换不作废，对端服务器零感知）→ ④读回为空（账号没设过 token）才最后走轮换兜底。开关 `NEWAPI_ADMIN_PAT_READBACK`（默认 1）。
- 登录逻辑重构：抽出 `_admin_session_login()`（只建会话不轮换，用完必归还）；`_admin_login()` 仅剩轮换兜底职责。读回的 PAT 同样强制落盘。
- 测试：两边 test_admin_cred_selfheal.py 各 15 个（+4 读回用例：成功不轮换/空回落轮换/异常回落/会话归还）。flovart 全量 **142 passed**；hewapi 135 passed + 5 个基线遗留失败（docs.js emoji 门禁，与本次无关）。
- 部署注意：两台服务器各自出镜像重启即可，无共享卷/无部署顺序要求。旧 admin_cred.json 缓存里的 PAT 若已失效，首个 401 会触发读回自愈。
- 风险备注：`/api/user/self` 是否返回 access_token 字段未经线上实证（验证需登录，铁律禁自动试）。若某版本把它抹掉 → 读回恒空 → 自动降级为轮换兜底（安全但退化回互踢风险），部署后看日志有无 "recovered by readback" 即知。

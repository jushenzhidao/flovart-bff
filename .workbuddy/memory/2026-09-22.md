## 🔴 CI 全红根因：time.monotonic() 初始化 bug（2026-09-22 17:45，已修复）

## 18:13 部署后 PAT 仍被覆盖 + 「退出登录导致 access_token 变化」疑云（源码核实）
- **new-api 源码核实（controller/auth_session.go AuthLogout）**：登出只做 `RevokeUserSession(sid,"logout")` + `RevokeByRefreshToken` + 清 refresh cookie，**完全不碰 users.access_token**。能改 PAT 字段的只有：GET/POST /api/user/token（GenerateAccessToken，注意新版本 GET 也生成）、DELETE /api/user/token（RevokeAccessToken）、UpdateUser 抬 auth_version 的连带作废。另：本版本登出路由是 `POST /api/user/auth/logout`，不存在 GET /api/user/logout。
- **真实成因**：部署期 PAT 被覆盖几次 = 每个新容器都是「从未轮换」进程（None 哨兵修复后本来就该这样放行第一次），而镜像/.env 里烧的 NEWAPI_ADMIN_PAT 在前几轮轮换后已失效 → 首次管理员调用 401 AUTH_UNAUTHORIZED → 语义分流放行 → 读回失败（该上游 /api/user/self 不回 access_token）→ 兜底轮换。两实例交替 ≈ 每 15 分钟变一次，冷静期只是限频不是根治。
- **「退出登录后又变了」= 时间撞车**，真凶是某家 BFF 后台管理员调用触发的兜底轮换。验证：grep 两家日志 `admin PAT rejected, re-login to rotate` / 轮换行。
- **止血顺序**：①从 DB users.access_token 直接抄当前有效值（别点控制台按钮，点了又轮换）→ ②同时写进两家 .env 的 NEWAPI_ADMIN_PAT + 确认 admin_cred.json 挂了持久卷 → ③重启两家容器。根治仍是独立管理员账号（create_admin_account.py，root 三次）。
- **飞哥实操踩坑（18:26）**：他反向操作——把 .env 里的过期 PAT 写进 DB，问为什么 DB 还一直变。原因：运行中的容器持有的是**内存/cred 文件里后来轮换出的值**（.env 只在启动时读），与 .env 旧值早已分叉 → 首个管理员调用 401 → 轮换覆盖 DB → 另一家又不匹配 → 循环。**活着的乒乓循环里手改 DB 永远写不赢**。正确序：先停两家容器冻结 → 取 DB 当前值（PAT 明文存储，写什么什么生效）→ 写进两家 .env → 再起容器。
- **18:32 真凶落定：flovart 登录流程本身就会轮换登录账号的 access_token**。`na.login()`（newapi_client.py:605）的固定链路 = `POST /api/user/login` 建会话 → `_mint_access_token()`（:568）`POST /api/verify`（password proof）→ **`GET /api/user/token` 换 PAT**（:600，语义=重新生成覆盖）→ 归还会话；PAT 塞进会话 Cookie（auth.py:97）。**用 uid=1 在任何 BFF 登录页登录 = 全站 PAT 轮换**，跟自愈/互踢无关。飞哥对齐完 .env 后用管理员号登了一次 flovart → DB 又变，就是这个。铁律：**uid=1 永远不在 BFF 前端登录**（测登录用普通号）；根治=三家独立管理号后，root 登录前端只轮换 root 自己的 token，无害。
- **18:34 日志甄别要点**：new-api 操作日志里 UA=python-httpx/0.27.2 + 服务器 IP = BFF 发起；UA=Mozilla + 用户出口 IP = 人直登 new-api 官方面板（BFF 只转发 X-Forwarded-For，不转发 UA）。**「重新生成 access_token」的事件特征 = 路由 GET/POST /api/user/token**；GET /api/user/self、GET /api/token/、POST /api/token/:id/key 全是只读、不轮换。new-api 官方面板的密码登录本身不轮换（源码已核）。⚠️ 运维坑：`docker compose restart` **不重读 .env**（env 在容器创建时注入），改完 .env 必须 `docker compose up -d` 重建容器，否则跑的还是旧过期 PAT —— 排「改了配置没生效」先查这个。

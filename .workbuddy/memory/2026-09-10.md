## 反推 Prompt 功能逻辑澄清（排查用）
- 入口：工作流节点工具栏 `WorkflowNodeToolbar.tsx`、素材库 `AssetLibraryBrowser.tsx`/`StudioMediaBrowser.tsx` 的"反推 Prompt"按钮 → `onReversePrompt`。
- 实现：`flovart-web/services/aiGateway.ts` 的 `reversePromptWithProvider` / `reversePromptStreamWithProvider`（2146 / 2285）。
- **关键事实**：走**前端 BYOK 直连多模态 LLM**，按用户配置的 text model 路由到 google/openai/anthropic/openrouter/custom，**直接 fetch 对应 provider 官方端点**（Google generateContent / Anthropic messages / OpenAI chat/completions）。
- **不经过 BFF 平台聊天 `/api/chat/completions`，不消耗 new-api 网关积分**。BFF 的 `CHAT_VISION_MODEL` 配置对「反推 Prompt」**无效**。
- 前置：本地/blob 图片 URL 必须转 base64 data URL（`ensureMultimodalDataUrl`）；模型必须是多模态（纯文本模型吃图 400）。未配用户 vision key → `requireApiKey` 抛错。
- 排查反推失败：先看用户是否配了 vision 模型 key（非 BFF 网关 key）；纯平台模式下反推不可用。

## 架构决策：Flovart 能力→模型由 model-plaza 映射驱动（方案 A）
飞哥指出：Flovart 图片能力在 BFF 硬编码端点（images/mask 等），model-plaza 模型映射 UI 配的 GPT Image 2 线路对 Flovart 不可见 → 编辑类按钮只能 400。
- **结论**：当前 Flovart 不看 model-plaza 映射，两层未打通；管理员 UI 配置对 Flovart 当前版本确实没生效（非 bug，是架构割裂）。
- **方案 A（已写文档 `docs/gateway-mapping-design.md`）**：model-plaza 模型映射 UI 作唯一事实来源；网关层新增「能力→产品模型」路由表（mask/outpaint/edits/annotate/relight/remove-bg 全部映射到同一个 `GPT Image 2` 产品模型；网关内部把这些能力端点**复用 `images/generations` 接口、按能力拼装参数**——是否带 `image`/`mask`/`prompt` 由 capability 决定，不需要独立的 edit 端点；upscale→必须独立超分模型不能接 GPT Image 2），网关收到 images/mask 后查映射再调真实模型。

## 终极修复：工作流 uid 所有权校验 + cloudSync 竞态防护（2026-09-10 晚）

- **终极方案——uid 所有权校验（最后一道防线）**：
  - `components/workflow/store.ts` 的 `workflowPersistStorage` 改造：
    - `setItem`：写入时在数据中嵌入 `_ownerUid: currentHostedUid()` 标签。

    - 消除了 cloudSync 与 App.tsx effect 之间的竞态条件（之前 cloudSync 可能在 App.tsx 清空前就开始读 store/拉云端）。
- 改动文件：`store.ts`（persist storage getItem/setItem）、`cloudSync.ts`（uid 切换重置逻辑）。`tsc` 零新增错误。

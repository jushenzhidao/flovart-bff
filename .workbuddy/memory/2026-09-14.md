# 2026-09-14

## 【修复】平台服务重复条目 + 管理员可编辑/删除（飞哥截图反馈）

飞哥截图：设置页「平台服务」区并列**两条一模一样**的 `OpenAI / https://api.chatfire.cn/v1`，
都是「只读」，问「想删除掉一个，发现没有编辑的地方」。

### 根因（两个问题叠加）

**问题 1：重复条目的来源 —— 去重键用了本机随机 id**
`SettingsPanel.handlePublishToPlatform` 原第 698 行按 `s.id !== entry.id` 去重，
而 `entry.id = itemKey.id` 是**本机 keyVault 的随机 id**。同一条服务在
导出/导入、清库重建后 id 会变；管理员先后用「本地两条不同 id 但内容相同」的条目发布，
服务端（`cloud_docs` uid=0/scope=platform/doc_key=services，**整体覆盖**语义）
就累积出两条相同服务。
→ 新增 `sameService(a, b)` 按**服务身份**（provider + baseUrl(去尾斜杠) + imageGenModel +
videoGenModel + defaultModel）判定同一条；发布时 `existing = 按 id 找 || 按身份找`，
沿用服务端已有条目的 id（而非本机 id）；`others` 过滤同时排除同 id 与同身份
（**顺带清掉历史遗留的重复项**）。

**问题 2：管理员无处可改 —— 平台服务区对所有人一视同仁只读**
原设计注释写「要改请让管理员去自己的设置页改后重新发布」，但实际上：
- 本机那几条（`managedApiKeys`）与服务端条目**未必一一对应**（本地可能已删、id 可能变过）
- 影子条目是服务端下发的，走 `onUpdateApiKey` 只会改本机、下轮拉取即被覆盖

→ 给**管理员**在「平台服务」区加内联编辑表单 + 删除按钮（普通用户保持只读）：
- `editingPlatformId` / `platformDraft` / `savingPlatform`（**与 BYOK 的 `editingKeyId` 分开管理**）
- `beginEditPlatform` / `cancelEditPlatform` / `savePlatformDraft`（整体覆盖服务端列表）
- `removePlatformServiceById(serviceId)`（按服务端 id 删，供编辑区与删除按钮复用）
- 表单字段：名称 / Base URL / API Key / 生图模型 / 视频模型 / 支持能力（text·image·video 复选）
- 删除/保存后调 `useHostedStore.getState().loadPlatformServices()` 立即刷新影子条目

### 踩坑
- 我一度引入 `var(--isl-accent)` —— **项目里没有这个变量**。实际用的是
  `--isl-mint`（主按钮底色）/ `--isl-mint-deep`（链接色）。已改正。
- 源码级测试断言里 `readFileSync(new URL(...))` 会被本机 fs broker shim 拦（`TypeError: The URL must be of scheme file`），
  **改用相对字符串路径** `readFileSync('components/SettingsPanel.tsx', 'utf8')` 即可。

### 经验
**「服务端下发 + 本机影子条目」的双层结构，一定要给数据真身所在的层留管理入口。**
只读展示对普通用户是对的，但对管理员必须有编辑/删除 —— 否则一个小改动就得去服务器改 SQLite。
另外：**跨设备/跨会话的资源去重，绝不能用本机随机 id 作键**，必须用「业务身份」。
